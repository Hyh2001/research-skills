# Lesson and Assessment Patterns

Use this reference before writing full lessons, practice tasks, quizzes, checkpoints, or answer keys.

## Attempt-First Lesson Flow

Each lesson should follow this shape unless the user requests a different format:

1. Real problem or question the lesson answers.
2. Short learner attempt or prediction before explanation.
3. Principle in plain language.
4. Worked example that shows why each step happens.
5. Contrasting example or counterexample.
6. Self-explanation prompts.
7. Partially completed task.
8. Independent task with notes closed.
9. Feedback and answer key in a separate file.
10. Corrected retry or new variation.
11. Exit ticket that mixes current and earlier lessons.

## First-Use Rule

Do not use a term the learner likely does not know without defining it at first substantive use.

Use this pattern:

```text
Term - plain definition; what distinguishes it from nearby ideas; why it matters here.
```

Judge novelty by the learner profile, not by the source author's vocabulary.

## Example to Principle

Every story, figure, case, or analogy must end with the transferable principle and at least one contrast.

The contrast can be:

- a different context where the same principle applies,
- a look-alike case where the principle does not apply,
- a failure case that reveals the boundary.

## Practice Design

Match practice to the capability:

- Recall capability -> free recall before multiple choice.
- Explanation capability -> short explanation plus required mechanism words.
- Calculation capability -> worked example, completion problem, independent problem.
- Method selection capability -> mixed cases where the method is not named.
- Critique capability -> claim, evidence, assumptions, boundary, counterexample.
- Implementation capability -> small runnable task or pseudo-code trace.

Require confidence ratings before answer reveal when possible:

```markdown
Confidence: 1 2 3 4 5
Answer:
Reason:
What would change my mind:
```

## Faded Support

Use this sequence:

```text
Worked example -> completion task -> independent task -> transfer task
```

Do not jump directly from explanation to a hard independent task unless the user is advanced or explicitly asks for a challenge.

## Answer Keys

Keep answer keys separate from learner-facing files. Name them consistently in `answers/`.

Good feedback includes:

- the expected answer,
- the key reasoning steps,
- common wrong answers,
- what the error reveals,
- a retry variation.

Avoid generic praise, hidden grading criteria, and answer keys that only state the final answer.

## Retention

Include spaced review for courses longer than one session:

- same day,
- next day,
- 3-7 days later,
- 14-30 days later for durable learning goals.

Each review should require retrieval or transfer, not rereading. Mix earlier items into later exit tickets.
